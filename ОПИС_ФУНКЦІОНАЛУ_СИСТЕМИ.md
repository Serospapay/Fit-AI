## Етап 1. Підготовка та налаштування проєкту

На початку я створив базову структуру проєкту та налаштував конфігурацію.

### Конфігурація через .env

Токен бота та інші налаштування зберігаються у файлі .env, щоб не залишати секрети в коді.

```python
# config.py
class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=Path(__file__).parent / ".env",
        env_file_encoding="utf-8",
    )
    BOT_TOKEN: str
    DB_NAME: str = "finance.db"
    REDIS_URL: str | None = None  # опційно для FSM
```

**Пояснення:** Pydantic автоматично читає змінні з .env файлу. Токен бота обов'язковий, решта має значення за замовчуванням.

### Точка входу та запуск бота

Головний файл main.py ініціалізує бота, підключає обробники та запускає опитування оновлень.

```python
async def main() -> None:
    bot = Bot(token=settings.BOT_TOKEN, ...)
    storage = MemoryStorage()  # або RedisStorage якщо є REDIS_URL
    dp = Dispatcher(storage=storage)
    register_handlers(dp)
    await init_db()
    await bot.set_my_commands(commands)
    await dp.start_polling(bot)
```

**Пояснення:** Бот створюється з токеном, підключаються всі обробники подій, ініціалізується база даних, встановлюються команди меню, після чого бот починає отримувати повідомлення від користувачів.

## Етап 2. Проєктування та створення бази даних

Другим кроком було створення бази даних для зберігання інформації про користувачів, транзакції та бюджети.

### Структура таблиць

```python
# Таблиця користувачів — зберігає ID та username з Telegram
CREATE TABLE users (
    user_id INTEGER PRIMARY KEY,
    username TEXT,
    created_at TIMESTAMP
);

# Таблиця транзакцій — кожна витрата або дохід
CREATE TABLE transactions (
    id INTEGER PRIMARY KEY,
    user_id INTEGER,
    type TEXT CHECK(type IN ('income', 'expense')),
    amount REAL,
    category TEXT,
    description TEXT,
    date DATE,
    created_at TIMESTAMP
);

# Таблиця бюджетів — ліміти на категорії
CREATE TABLE budgets (
    id INTEGER PRIMARY KEY,
    user_id INTEGER,
    category TEXT,
    amount REAL,
    period TEXT CHECK(period IN ('month', 'year')),
    UNIQUE(user_id, category, period)
);
```

**Пояснення:** Три основні таблиці. Користувачі реєструються при першому /start. Транзакції — це всі доходи та витрати. Бюджети дозволяють задати ліміт на категорію на місяць або рік. Індекси на user_id та date прискорюють запити.

### Контекстний менеджер для підключення

```python
@asynccontextmanager
async def get_connection():
    async with aiosqlite.connect(settings.DB_NAME) as conn:
        yield conn
```

**Пояснення:** Кожен запит до бази використовує цей менеджер. Після виконання з'єднання автоматично закривається, що запобігає витокам пам'яті.

## Етап 4. Додавання транзакцій (витрати та доходи)

Наступним кроком була реалізація додавання витрат і доходів через діалог з кроками.

### FSM стани для транзакції

```python
class TransactionState(StatesGroup):
    waiting_for_date = State()      # вибір дати
    waiting_for_amount = State()    # введення суми
    waiting_for_description = State()  # опис (можна пропустити)
```

**Пояснення:** FSM (машина станів) запам'ятовує, на якому кроці зараз користувач. Спочатку вибір категорії, потім дати, суми, опису. Без FSM бот не знав би, що очікувати від наступного повідомлення.

### Потік додавання транзакції

1. Користувач натискає «Витрата» або «Дохід»
2. Обирає категорію зі списку (Їжа, Транспорт, Житло тощо)
3. Обирає дату: Сьогодні, Вчора або Пропустити
4. Вводить суму (перевіряється валідація)
5. Вводить опис або «-» щоб пропустити
6. Транзакція зберігається, показується новий баланс

```python
@router.message(TransactionState.waiting_for_amount, F.text)
async def process_amount(message: Message, state: FSMContext) -> None:
    is_valid, amount = validate_amount(message.text)
    if not is_valid:
        await message.answer("Помилка! Введіть коректну суму...")
        return
    await state.update_data(amount=amount)
    await state.set_state(TransactionState.waiting_for_description)
    await message.answer("Введіть опис...", reply_markup=cancel_button_kb())
```

**Пояснення:** validate_amount перевіряє, чи число коректне та не перевищує ліміт. Якщо так — зберігаємо в state і переходимо до наступного кроку. Кнопка «Відмінити» дозволяє вийти з діалогу в будь-який момент.

### Швидкі витрати

Режим «Швидко» показує популярні категорії (Їжа, Кава, Транспорт тощо) одним кліком. Дата автоматично ставиться «сьогодні», щоб прискорити введення.

```python
@router.callback_query(F.data.startswith("quick_cat_"))
async def quick_category(callback: CallbackQuery, state: FSMContext) -> None:
    parts = callback.data.split("_", 3)
    trans_type, category = parts[2], parts[3]
    today_str = datetime.now().strftime("%Y-%m-%d")
    await state.update_data(
        category=category, transaction_type=trans_type, transaction_date=today_str
    )
    await state.set_state(TransactionState.waiting_for_amount)
    await callback.message.edit_text(
        f"Швидка витрата\n\nКатегорія: {category}\nВведіть суму:",
        reply_markup=cancel_button_kb(),
    )
```

**Пояснення:** При натисканні швидкої категорії дата одразу ставиться «сьогодні», і користувач переходить прямо до введення суми. Це економить кілька кліків порівняно з повним діалогом.

## Етап 5. Баланс та звіти

Після цього реалізовано перегляд балансу та текстових звітів за період.

### Розрахунок балансу

Баланс = сума всіх доходів мінус сума всіх витрат. Для оптимізації використовується один SQL-запит замість двох:

```python
async def get_balance(user_id: int):
    async with db.execute(
        """SELECT
            COALESCE(SUM(CASE WHEN type = 'income' THEN amount ELSE 0 END), 0),
            COALESCE(SUM(CASE WHEN type = 'expense' THEN amount ELSE 0 END), 0)
        FROM transactions WHERE user_id = ?""",
        (user_id,),
    ) as cursor:
        row = await cursor.fetchone()
        total_income, total_expense = row[0], row[1]
        return total_income, total_expense, total_income - total_expense
```

**Пояснення:** Один запит рахує і доходи, і витрати через CASE. Це швидше, ніж два окремі SELECT.

### Звіти за період

Користувач обирає період: Сьогодні, Вчора, Тиждень, Місяць, Рік або Весь час. Для «Місяць» та «Рік» використовуються календарні періоди (поточний місяць з 1-го числа, поточний рік з 1 січня).

```python
def get_period_dates(period: str):
    """Отримати дати початку та кінця періоду"""
    today = datetime.now()
    if period == "today":
        start_date, end_date = today, today
        period_name = "Сьогодні"
    elif period == "month":
        start_date = today.replace(day=1)
        end_date = today
        period_name = "Поточний місяць"
    elif period == "year":
        start_date = today.replace(month=1, day=1)
        end_date = today
        period_name = "Поточний рік"
    # ... інші періоди
    return start_date.strftime("%Y-%m-%d"), end_date.strftime("%Y-%m-%d"), period_name

@router.callback_query(F.data.startswith("report_"))
async def generate_report_handler(callback: CallbackQuery) -> None:

    start_date, end_date, period_name = get_period_dates(period)

    await safe_edit_or_answer(callback.message, report, reply_markup=reports_menu_kb())
```

**Пояснення:** get_period_dates перетворює назву періоду на конкретні дати. generate_report збирає транзакції за цей діапазон, рахує суми по категоріях і формує текстовий звіт. safe_edit_or_answer показує звіт, а при помилці (наприклад, під фото) надсилає нове повідомлення.

## Етап 6. Бюджети та сповіщення

Далі додано можливість встановлювати бюджети на категорії та отримувати попередження.

### Встановлення бюджету

Користувач обирає категорію витрат, період (місяць/рік) та вводить суму. У базі зберігається один бюджет на пару (категорія + період) завдяки UNIQUE(user_id, category, period). При повторному встановленні старий запис замінюється (INSERT OR REPLACE).

```python
# database.py
async def set_budget(user_id: int, category: str, amount: float, period: str):
    async with get_connection() as db:
        await db.execute(
            '''INSERT OR REPLACE INTO budgets (user_id, category, amount, period)
               VALUES (?, ?, ?, ?)''',
            (user_id, category, amount, period)
        )
        await db.commit()

# handlers/budgets.py
@router.message(BudgetState.waiting_for_amount, F.text)
async def budget_process_amount(message: Message, state: FSMContext) -> None:
    is_valid, amount = validate_amount(message.text)
    if not is_valid:
        await message.answer("Помилка! Введіть коректну суму.")
        return
    data = await state.get_data()
    category, period = data.get("budget_category"), data.get("budget_period")
    await set_budget(message.from_user.id, category, amount, period)
    await message.answer(f"Бюджет встановлено!\nКатегорія: {category}\nСума: {amount:.2f} грн")
    await state.clear()
```

**Пояснення:** INSERT OR REPLACE замінює існуючий бюджет на ту саму категорію і період. FSM зберігає категорію та період з попередніх кроків, а на останньому кроці користувач вводить лише суму.

### Перевірка при додаванні витрати

Після кожної нової витрати викликається check_and_notify_budget. Якщо витрачено 80% бюджету — надсилається попередження, якщо 100% і більше — сповіщення про перевищення.

```python
async def check_and_notify_budget(message: Message, category: str) -> None:
    budget_amount, spent_amount = await check_budget(...)
    if budget_amount and budget_amount > 0:
        percentage = (spent_amount / budget_amount) * 100
        if percentage >= 100:
            await message.answer("Увага! Бюджет перевищено...")
        elif percentage >= 80:
            await message.answer("Увага! Витрачено 80% бюджету...")
```

**Пояснення:** Функція перевіряє, чи є бюджет на цю категорію, рахує відсоток витрат і надсилає повідомлення, якщо потрібно.

### Пагінація історії

Транзакції показуються по 5 на сторінку. Кнопки «назад» та «вперед» дозволяють переходити між сторінками. Для кожної транзакції є кнопка «Видалити».

```python
# database.py
async def get_recent_transactions(user_id: int, limit: int = 10, offset: int = 0):
    async with get_connection() as db:
        async with db.execute(
            '''SELECT * FROM transactions WHERE user_id = ?
               ORDER BY date DESC, created_at DESC LIMIT ? OFFSET ?''',
            (user_id, limit, offset)
        ) as cursor:
            transactions = await cursor.fetchall()
        async with db.execute(
            'SELECT COUNT(*) FROM transactions WHERE user_id = ?', (user_id,)
        ) as cursor:
            total = (await cursor.fetchone())[0]
    return transactions, total
```

## Етап 8. Графіки та експорт

На цьому етапі додано візуалізацію та експорт даних.

### Кругові діаграми

Matplotlib будує кругові діаграми витрат і доходів по категоріях за останній місяць. Оскільки шрифт DejaVu Sans не підтримує емодзі, з підписів категорій прибираються емодзі через regex, щоб уникнути попереджень.

```python
def _strip_emoji_for_chart(text: str) -> str:
    """Прибрати емодзі з підписів для matplotlib"""
    emoji_pattern = re.compile(r"[\U0001F300-\U0001F9FF\U00002600-\U000027BF]+", flags=re.UNICODE)
    result = emoji_pattern.sub("", text).strip()
    return result if result else "?"

async def generate_pie_chart(user_id: int, trans_type: str, period_name: str):
    categories = await get_category_summary(user_id, start_date, end_date, trans_type)
    labels = [_strip_emoji_for_chart(cat[0]) for cat in categories]
    sizes = [cat[1] for cat in categories]
    fig, ax = plt.subplots(figsize=(10, 8))
    ax.pie(sizes, labels=labels, autopct='%1.1f%%', colors=plt.cm.Set3(range(len(labels))))
    buf = io.BytesIO()
    plt.savefig(buf, format='png', dpi=100, bbox_inches='tight')
    buf.seek(0)
    return buf
```

**Пояснення:** get_category_summary повертає категорії та суми. _strip_emoji_for_chart прибирає емодзі, щоб matplotlib не падав. Графік зберігається в BytesIO і повертається як об'єкт для відправки фото в Telegram.

### Графік динаміки

Лінійний графік показує доходи та витрати по місяцях за рік. Використовується pandas для групування даних.

```python
async def generate_dynamics_chart(user_id: int):
    transactions = await get_transactions(user_id, start_date, end_date)
    df = pd.DataFrame(transactions, columns=['id', 'user_id', 'type', 'amount', ...])
    df['date'] = pd.to_datetime(df['date'])
    df['month'] = df['date'].dt.to_period('M')
    monthly_income = df[df['type'] == 'income'].groupby('month')['amount'].sum()
    monthly_expense = df[df['type'] == 'expense'].groupby('month')['amount'].sum()
    all_months = pd.period_range(start=df['month'].min(), end=df['month'].max(), freq='M')
    monthly_income = monthly_income.reindex(all_months, fill_value=0)
    monthly_expense = monthly_expense.reindex(all_months, fill_value=0)
    ax.plot(x, monthly_income.values, marker='o', label='Доходи', color='green')
    ax.plot(x, monthly_expense.values, marker='o', label='Витрати', color='red')
    plt.savefig(buf, format='png', dpi=100)
    return buf
```

**Пояснення:** pandas групує транзакції по місяцях. reindex заповнює пропущені місяці нулями, щоб графік був безлінійним. Дві лінії — доходи та витрати — показують динаміку за рік.

### Експорт в Excel та CSV

Користувач може експортувати всі транзакції в Excel (.xlsx) або CSV. Файл генерується в пам'яті та надсилається через BufferedInputFile.

```python
async def export_to_excel(user_id: int):
    transactions = await get_transactions(user_id)
    df = pd.DataFrame(transactions, columns=['ID', 'User ID', 'Тип', 'Сума', 'Категорія', 'Опис', 'Дата', 'Створено'])
    buf = io.BytesIO()
    with pd.ExcelWriter(buf, engine='openpyxl') as writer:
        df.to_excel(writer, index=False, sheet_name='Транзакції')
    buf.seek(0)
    return buf

async def export_to_csv(user_id: int):
    transactions = await get_transactions(user_id)
    df = pd.DataFrame(transactions, columns=['ID', 'User ID', 'Тип', 'Сума', ...])
    buf = io.BytesIO()
    buf.write(df.to_csv(index=False, encoding='utf-8-sig').encode('utf-8-sig'))
    buf.seek(0)
    return buf

# handler
doc = BufferedInputFile(excel_file.read(), filename=f"finance_{datetime.now().strftime('%Y%m%d')}.xlsx")
await callback.message.answer_document(document=doc, caption="Ваші фінансові дані")
```

**Пояснення:** pandas створює DataFrame з транзакцій. ExcelWriter з openpyxl записує в .xlsx. Для CSV використовується utf-8-sig, щоб Excel коректно відкривав кирилицю. BufferedInputFile дозволяє надіслати файл з пам'яті без збереження на диск.

## Етап 9. Покращення навігації та обробка помилок

На фінальному етапі покращено зручність та стабільність роботи.

### Кнопка «Головна» скрізь

На всіх екранах (звіти, графіки, експорт, бюджети, баланс) додано кнопку «Головна» для швидкого повернення. У списку бюджетів є також кнопка «Назад» до меню бюджетів.

```python
# Приклад: меню графіків з кнопкою Головна
def charts_menu_kb():
    return InlineKeyboardMarkup(inline_keyboard=[
        [InlineKeyboardButton(text="Витрати по категоріях", callback_data="chart_expense_month")],
        [InlineKeyboardButton(text="Динаміка за рік", callback_data="chart_dynamics_year")],
        [
            InlineKeyboardButton(text="До звітів", callback_data="reports"),
            InlineKeyboardButton(text="Головна", callback_data="back_main"),

    ])
```

**Пояснення:** Кожна inline-клавіатура містить кнопку з callback_data="back_main", яка повертає користувача на головний екран. Це зручно, коли він «загубився» в глибокому меню.

### Безпечна обробка edit_text

Коли користувач натискає кнопку під фото або документом (наприклад, «До звітів» під графіком), edit_text не працює — у повідомленні немає тексту. Тому використовується функція safe_edit_or_answer: спочатку викликається edit_text, при помилці — надсилається нове повідомлення через answer().

```python
async def safe_edit_or_answer(msg: Message, text: str, ...) -> None:
    try:
        await msg.edit_text(text, ...)
    except TelegramBadRequest:
        await msg.answer(text, ...)
```

**Пояснення:** Якщо не вдалося відредагувати повідомлення (фото, документ, застаріле), надсилаємо нове. Користувач у будь-якому випадку отримує потрібну інформацію.

### Захист від подвійного запуску

Щоб уникнути помилки «Conflict: make sure only one bot instance is running», при запуску створюється lock-файл з PID процесу. Якщо вже є запущений екземпляр, новий не стартує і виводить повідомлення.

```python
LOCK_FILE = Path(__file__).parent / ".finbot.lock"

def check_another_instance() -> bool:
    """Перевірка чи вже запущений інший екземпляр бота"""
    if not LOCK_FILE.exists():
        return False
    try:
        pid = int(LOCK_FILE.read_text().strip())
        os.kill(pid, 0)  # перевірка чи процес існує (сигнал 0)
        return True
    except (ValueError, OSError, ProcessLookupError):
        LOCK_FILE.unlink(missing_ok=True)  # застарілий lock
        return False

if __name__ == "__main__":
    if check_another_instance():
        print("Помилка: Бот вже запущений. Зупиніть інший екземпляр.")
        sys.exit(1)
    create_lock()
    try:
        asyncio.run(main())
    finally:
        remove_lock()
```

**Пояснення:** os.kill(pid, 0) не вбиває процес, а лише перевіряє його існування. Якщо процес вже не існує — lock вважається застарілим і видаляється. create_lock записує PID поточного процесу, remove_lock викликається при завершенні (навіть при помилці) через try/finally.
